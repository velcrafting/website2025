## Discovery example

**What we heard:** Team members often repeat the same product questions, and useful answers are scattered across documents.

**Goal:** Determine whether a small, maintained knowledge collection could help people find reliable information.

**Constraint:** The first exploration uses fictional content. Any use of real internal documents requires a separate data and access decision.

**Open question:** Who should own corrections when the underlying information changes?

## Proposal overview example

Review the information flow and build a bounded prototype that shows an answer, its source and an explicit unknown state.

**Illustrative deliverables:** A current-state map, a small fictional knowledge collection, a prototype journey and a recommendation about the next phase.

**Done when:** A reviewer can trace an example answer to its source, see an honest response to an unsupported question, and understand the prototype's limitations.

**Excluded:** Production rollout, access to real client systems, automatic publication and ongoing support. No separate quote stage is shown in this example; a real engagement's commercial record would be restricted to its authorized audience.

## Start example
